# Current FO theory: capabilities and limits

This document summarizes `EVALUATION.md`. It distinguishes supported operations,
the soundness guarantee for certified results, and abilities that are absent or
not guaranteed. It records the evaluation snapshot; no additional proof-search
runs or compilations were performed to prepare it.

## 1. Main conclusion

**The current implementation is a soundness-backed, bounded proof-producing
prover for positive first-order DNF sequents with inductively defined predicates.
It is not a complete first-order decision procedure, and it has not yet met the
all-nine fully certified benchmark target.**

It can define and manipulate this FO fragment, apply checked inference rules,
search for finite acyclic/cyclic proofs, synthesize routing witnesses, and turn
successfully checked certificates into semantic validity theorems.

It does not guarantee finding every valid proof, reproducing every original
OCaml acceptance decision, or completing a search within practical time and
memory limits.

## 2. What the current theory can do

### A. Represent, parse and validate the supported FO fragment

The implementation supports:

- Integer constant symbols, free/existential variables, and nested named
  function applications.
- Equality, disequality, and logically tagged inductive predicate atoms.
- Conjunction products and disjunctions of products: positive disjunctive normal
  form (DNF).
- Sequents with an antecedent and a succedent.
- Finite positive inductive clause definitions, including mutual recursion,
  constructor-pattern heads, repeated head variables and equality/disequality
  guards.

It can parse the original supported input forms, collect variables recursively,
allocate names/tags deterministically, and diagnose undefined predicates,
invalid arities, definition-header mismatches and forbidden antecedent
existential variables.

The adopted variable discipline is explicit: free variables are universally
quantified by validity; existential witnesses are local to each right-hand
product; antecedents contain only free/eigenvariables.

**Relevant files:** `Syntax.v`, `Definitions.v`, `Input.v`.

### B. Perform substitutions and matching

It implements simultaneous substitution, freshening/renaming operations,
directional matching, repeated-head matching with equality constraints, and
subsumption used in weakening and backlink planning.

Matching is used to propose applications. The checked compiler independently
validates the native rule instance and expected labels; a matcher result alone
is not accepted as proof evidence.

**Relevant files:** `Substitution.v`, `Matching.v`, `RuleGeneration.v`,
`Compiler.v`.

### C. Give predicates a rigorous inductive meaning

Predicate interpretations are simultaneous least fixed points generated by
finite positive clause derivations. The implementation proves stage
monotonicity, unfolding/closure, leastness, and the equivalence between ordinary
sequent validity and the bounded-occurrence worlds used by cyclic descent.

Validity ranges over general nonempty models satisfying exactly the required
constructor laws:

- Unary `s` is injective.
- Binary `cons` is jointly injective.
- `0` is neither an `s` value nor a `cons` value.

No general arithmetic interpretation, distinctness of every integer constant,
injectivity of arbitrary functions, or free-constructor universe is assumed.

**Relevant files:** `Semantics.v`, `Rank.v`.

### D. Apply the intended checked rule families

Generic theorem-backed constructors cover:

- Identity and contradiction.
- Trivial equality removal, left equality substitution, right existential
  equality substitution, right-atom discharge, constructor injectivity, and
  right congruence.
- Left disjunction and guarded right conjunction.
- Right-hand existential instantiation.
- Right unfolding and contraction-style left unfolding.
- Folding, weakening, backwards substitution and exact backlinks.

Each constructor has checked side conditions. For example, some administrative
and left-changing rules require singleton antecedents, constructor rules require
the supported arities, and scoped substitutions must avoid existential capture.

**Relevant files:** `Rules.v`, `LocalRules.v`, `Unfolding.v`, `Compiler.v`.

### E. Search generically for acyclic and cyclic proofs

The search engine supports bounded iterative deepening, demand-driven DFS,
rule macros, backlink preparation, and fold-followed-by-backlink search. It
examines supplied definitions and sequents rather than dispatching on benchmark
names. Renamed and modified predicate libraries have been demonstrated.

The core is independent of Cyclic/LTL. The adapter uses the existing Cyclic
framework to execute proof-graph operations and certify completed graphs.

Logical tags can be shared, while internal occurrence-specific trace identifiers
permit separately justified rank transport. The adapter converts them to dense
framework identifiers.

**Relevant files:** `Search.v`, `LazySearch.v`, `FastGeneration.v`, `Adapter.v`,
`CertifiedSearch.v`.

### F. Produce and check certificates

The implementation synthesizes the framework's fixed-per-node routing witness,
checks trace transitions and potentials, and derives graph-wide semantic
certificate obligations generically.

The principal public guarantee is:

```text
Prover.prove limits goal = Some p  ->  valid Definitions goal
```

This is established by `prove_sound`/`proved_sound`. A `proved goal` contains
both full framework checker acceptance and equality of the graph root with the
requested goal. Thus a kernel-accepted result proves that particular goal under
the stated semantics, rather than merely an anticipated or different label.

The proofs use audited standard-library classical reasoning and
description/choice principles. The audit found no `Admitted`, new project proof
axioms, or disabled checking mechanisms.

**Relevant files:** `Certification.v`, `Witness.v`, `SealedCompiler.v`,
`CertifiedSearch.v`.

## 3. What it cannot do, or is not guaranteed to do

| Ability | Current limit |
| --- | --- |
| Decide arbitrary first-order logic | Unsupported: the language is positive DNF, not a general AST with arbitrary negation, implication and explicit quantifier binders. |
| Accept existential variables in antecedents | Rejected by the adopted input/scope discipline. |
| Accept negative recursive predicate definitions | Unsupported: inductive definitions must be positive. |
| Treat undefined predicates as arbitrary external relations | Not supported by the agreed validation policy; undefined names are errors. |
| Automatically solve general arithmetic | No general arithmetic decision procedure is implemented. Arithmetic-looking relations are reasoned about through their supplied clauses and model assumptions. |
| Prove every valid supported sequent | Not guaranteed. Search, matching and enumeration are bounded and incomplete. |
| Return a countermodel when proof search fails | No such result is provided. `None`, `Unknown` and timeout do not establish invalidity. |
| Accept every cyclic graph accepted by the original trace criterion | Not guaranteed. The frozen framework requires a more restrictive fixed-node routing witness. A regression demonstrates a difference between the two acceptance formats. |
| Resume alternatives after the full packaging check rejects a graph | Not currently implemented: `prove` returns `None` after that rejection. |
| Preserve `sequent_wfb` for every arbitrary local-rule application | Not universally proved. Semantic soundness of a rule is distinct from preservation of this validation invariant. |
| Finish within practical resource limits | Not guaranteed. Contraction, branching, matching, dependent evidence and relational checking can cause large time/memory costs. |
| Exactly reproduce the OCaml implementation | Not guaranteed. Demonstrated defects are corrected, and representations, freshness, internal traces and candidate ordering differ. No whole-program equivalence theorem is claimed. |
| Use the complete literal source definition library immediately | Blocked by the unresolved `ADD_2` reference. The literal transcription diagnoses it; examples use an explicitly validated closed subset. |
| Automatically benefit from the relevance heuristic | Not yet: `Relevance.v` is implemented/tested separately but is not wired into active search. |
| Guarantee all artifacts are verified against the latest integration | Not yet: downstream examples/benchmarks require rebuilding, and the broader kernel-check run was interrupted. |

These limits do not weaken the conditional soundness theorem for successfully
constructed and kernel-accepted `proved` results. They concern supported scope,
proof discovery, coverage, performance, invariants and verification status.

## 4. What has actually been demonstrated

The last completed runs, before final evidence-sealing integration, established:

| Evidence level | Demonstrated cases |
| --- | --- |
| Full checked examples | Equality identity; `true |- N(0)`; cyclic `O(x) |- N(x)`; renamed/modified `Entry`/`Tally` examples. |
| Full checked source benchmarks | 01: odd implies natural; 04: natural implies odd/even; 07: addition zero right. |
| Raw source graphs found, full packaging unfinished | 02: even/odd implies natural; 09: addition successor right; 14: naturals imply `N2`. |
| No successful graph returned in the reported larger runs | 05: naturals imply `Q`; 08: addition preserves naturalness; 13: naturals imply hydra. Runs exhausted smaller budgets or timed out. |

These observations do not prove that the unfinished targets are impossible for
the implementation. In particular, no inherent trace-format obstruction has
been established for those three search failures.

The larger dependent certificates and previously checked examples have not
been freshly verified against the final sealing integration. `Examples.v` and
`BenchmarkRuns.v` are the identified dependency-stale artifacts.

## 5. How to interpret the results

| Result | Meaning |
| --- | --- |
| Parser/validation success | The input belongs to the validated supported syntax and scope. It is not a proof. |
| `search_graph` returns `Found` | A candidate graph passed the search's structural/routing acceptance. It is not the final public certificate result. |
| `prove` returns `Some p` | A full certificate for the requested goal is available; `proved_sound` derives native semantic validity. |
| `search_graph` returns `Unknown` | This bounded search attempt did not produce an accepted graph; it does not refute the goal. |
| `prove` returns `None` | Validation, search or final packaging did not yield a certificate; the goal may still be valid. |
| Process timeout or resource failure | The computation did not finish; no logical conclusion follows. |

**Practical conclusion:** use the current theory as a sound, extensible,
proof-producing FO implementation with demonstrated cyclic proofs and explicit
failure/coverage limits. Do not currently rely on it as a complete or uniformly
efficient replacement for all behavior of the original FO prover.
